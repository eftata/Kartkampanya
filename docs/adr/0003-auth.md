# 0003 — Kimlik: Auth.js v5, veritabanı oturumları, iki katmanlı kontrol

- **Durum:** Kabul edildi
- **Tarih:** 2026-10-14

## Bağlam

ROADMAP Auth.js ile magic link + Google girişi öngörüyor. Auth.js v5 (`next-auth@5`) hâlâ beta
(5.0.0-beta.32); npm `latest` v4'ü gösteriyor. Next.js 16'da Cache Components açık: oturum okuyan
bileşenler `<Suspense>` içinde olmalı, layout'un tepesinde oturum beklenmemeli.

## Karar

- `next-auth@5.0.0-beta.32` sabitlenir (tam sürüm, `^` yok); `@auth/prisma-adapter` ile
  **veritabanı oturumları** (`Session` tablosu). Oturumlar sunucudan iptal edilebilir; KVKK hesap
  silmede kullanıcının tüm oturumları silinir.
- Yapılandırma `NextAuth(() => config)` ile tembel kurulur; build veritabanı gerektirmez.
- Giriş yöntemleri: Nodemailer (magic link, Türkçe şablon, 24 saat geçerli, tek kullanımlık) ve
  Google (yalnızca `AUTH_GOOGLE_ID/SECRET` tanımlıysa). Google e-postayı doğruladığı için aynı
  e-postalı hesaba bağlanmasına izin verilir (`allowDangerousEmailAccountLinking`).
- Erişim kontrolü iki katmanlı:
  1. `proxy.ts` — iyimser: oturum çerezi yoksa korumalı yoldan landing'e (`/`) yönlendirir.
  2. `lib/auth/session.ts` — `requireUser()`: oturumu gerçekten doğrular. Korumalı layout'larda
     `<Suspense>` içindeki `UserMenu` bunu çağırır; kullanıcıya özel veri okuyan her sayfa ve
     Server Action da çağırmalıdır.
- `deletedAt` dolu hesaplar giriş yapamaz.
- `next.config.ts`, monorepo kökündeki `.env`'yi `@next/env` ile yükler.

## Sonuçlar

- `/giris` sayfasındaki Google butonu build anındaki ortam değişkenine göre statik iskelete girer;
  Google anahtarları eklendikten sonra yeniden build gerekir.
- v5 kararlı sürüme geçtiğinde (veya proje bakım moduna alınırsa) bu ADR yeniden değerlendirilir.
- Admin rol kontrolü (`role = ADMIN`) Sprint 1'de `requireAdmin()` olarak eklenecek.
